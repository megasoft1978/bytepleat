How it works

Three views in the desktop alpha.

Each view asks for a source, a place for the result where one applies, and a single run. File choices use your system’s dialogs.

  • Create

    Choose files or a folder, pick ZIP, 7z or a compressed tar format, and choose where the new archive is saved. Your originals are not moved or removed.

  • Extract

    Choose one archive and a destination folder. Bytepleat decodes into private staging first, then publishes a new folder. If that folder already exists, the job stops.

  • Inspect

    Look through an archive’s entries without extracting. The list does not check file contents, so test or extract when integrity matters. A compressed tar is listed by fully decoding it into private temporary staging, removed afterwards; extracting selected entries decodes it again.

Careful by default

Built around the boring, important parts.

Local processing
Files are processed on your device. Nothing is uploaded.
Originals untouched
Creating or extracting never moves, changes or deletes your source files.
No overwriting in the desktop app
The desktop app refuses an existing archive file or extraction folder rather than replacing it. The CLI also refuses by default, but --force replaces an existing named output file; extraction always needs a new folder.
Bounded work
Desktop jobs cap decoded output at 1 GiB and archives at 100,000 entries, and fail before publishing when a limit is hit.

Formats

Familiar archives, clear boundaries.

Each format is a bounded subset of what the standard allows. See the format notes and compression research.

  • .zip

    ZIP

    Classic Stored and Deflate entries only.

  • .7z

    7z

    A bounded subset. New archives are written with LZMA2.

  • .tar.zst

    Tar + Zstandard

    Pack a folder, or open a compressed tar.

  • .tar.gz

    Tar + gzip

    Pack a folder, or open a compressed tar.

  • .tar.lz4

    Tar + LZ4

    Pack a folder, or open a compressed tar.

Not supported

RAR is not decoded. Password-protected archives and ZIP64 are not supported. A file with a supported extension can still be refused if it falls outside these subsets.

The CLI also handles Zstandard, gzip and LZ4 byte streams, plus typed Pco numeric streams that require an explicit data type. Pco is not a general file or CSV compressor; see the format notes.

Good to know

Questions, plainly answered.

Is the desktop app ready to download?

Not yet. It is an alpha and no desktop installer is offered here. See platform status for what has been checked, or the desktop README to build it from source. The command-line tool is the released download.

Can I open RAR archives?

No. RAR files are not supported for extraction. Use a compatible archive tool to extract them first.

Can I open password-protected or ZIP64 archives?

No. Those archive features are not supported by the current desktop app. See the format guide for supported subsets.

Does Inspect check an archive’s contents?

No. Inspect shows a bounded entry list only; ZIP and 7z are listed from their metadata without decoding file contents. A compressed tar can only be listed by fully decoding it into private temporary staging, which is removed afterwards and keeps nothing. Extraction decodes and checks the supported archive contents before files are published, and extracting selected entries decodes the whole archive again before keeping the ones you chose.

Does Bytepleat change my original files?

No. Creating an archive leaves the selected originals in place, and extraction writes only into a new folder. The desktop app never overwrites an existing file or folder. The CLI refuses an existing output by default too, but --force replaces an existing named output file.
